# Як це працює

## Проблема
Claude Code (на вашому комп'ютері), чат claude.ai (браузер, телефон) і Cowork мають кожен свою пам'ять. Те, що ви пояснили в одному місці, в інших невідоме. Цей набір дає їм **одну спільну пам'ять** лише вбудованими засобами: файли на комп'ютері, скіли й конектор Google Диска.

## Ідея: одне джерело правди і дві «скриньки»

```
                 ┌──────────────────────────── ваш комп'ютер ───────────────────────────────────┐
                 │  робоча папка (відкрита в Claude Code)                                       │
                 │    CLAUDE.md · JOURNAL.md · memory/MEMORY.md · <проєкт>/docs/CONTEXT.md       │
                 └───────────────┬───────────────────────────────────────────▲─────────────────┘
       скіл task-summary,        │ експорт: свіжий документ MEMORY            │ імпорт: документи INBOX → файли,
       після кожної задачі       ▼                                            │ ✅ і в архів
                 ┌──────────────────────── Google Диск: Claude-memory ────────┴─────────────────┐
                 │   MEMORY (Google-документ)   INBOX/ (документ на розмову)     archive/        │
                 └───────────────┬───────────────────────────────────────────▲─────────────────┘
       скіл shared-memory,       │ читає на початку                           │ пише наприкінці
       кожна розмова             ▼                                            │
                 ┌──────────────────────── чат claude.ai · Cowork ───────────────────────────────┐
                 └───────────────────────────────────────────────────────────────────────────────┘
```

- **Комп'ютер — джерело правди.** Правила, факти, контекст проєктів і журнал лежать у звичайних Markdown-файлах робочої папки. Claude Code читає їх на початку кожної сесії (через `CLAUDE.md`).
- **Code → чат.** Після кожної завершеної задачі скіл `task-summary` оновлює `memory/MEMORY.md` (до 300 рядків) і кладе його на Диск свіжим Google-документом `MEMORY`. Попередній переноситься в `archive`.
- **Чат → Code.** На початку розмови скіл `shared-memory` читає `MEMORY`. Наприкінці суттєвої розмови він створює **один новий Google-документ** у `INBOX` з коротким підсумком за шаблоном.
- **Імпорт.** На початку кожної сесії Claude Code і в `task-summary` Claude Code переглядає `INBOX`, переносить кожен запис у журнал, контекст проєкту й пам'ять, додає ✅ до назви документа й переносить його в `archive`. Нічого не видаляється.
- **Знімки в скілах (необов'язково).** Скіли профілю й компанії з [claude-deep-context](https://github.com/kuzubis/claude-deep-context) — стислі знімки на випадок, коли Диск недоступний.
- **Резервна копія (необов'язково).** `sync/sync.ps1` кожні 30 хв відправляє всю робочу папку в закрите сховище GitHub і дзеркалить на Google Диск, разом із власною пам'яттю Claude Code (`memory/code/`).

## Обмеження (перевірено на практиці)
| Обмеження | Що робимо |
|---|---|
| Конектор Google Drive уміє створювати, перейменовувати, переносити й читати файли, але **не дописує текст в уже наявний Google-документ** (для цього потрібен конектор Google Docs, якого часто немає). | Один новий документ на кожен підсумок у `INBOX`; `MEMORY` щоразу замінюється свіжим документом, старий — в `archive`. |
| **Пошук за назвою відстає** на кілька хвилин: одразу після перейменування повертає стару назву й папку. | Завжди переглядати папку лише за `parentId = '<ID>'`, назву звіряти у відповіді. |
| Скіл сам на початку чату не запускається. | Абзац в **особистих налаштуваннях** claude.ai велить кожному чату спершу застосувати `shared-memory`. |
| Одиничні переноси рядків у завантаженому Markdown зливаються в один абзац. | Поля підсумку пишемо пунктами списку. |
| `robocopy /MIR` робить копію на Диску точним дзеркалом і видаляє все, що туди додали вручну. | Чат пише лише в окрему папку `Claude-memory`, ніколи в дзеркальну копію. |
| Скіли в claude.ai завантажуються вручну (zip). | `tools/build-skill-zips.py` збирає правильні zip (зі звичайними слешами: `Compress-Archive` у Windows PowerShell 5.1 пише обернені). |
| Деякі режими дозволів Claude Code блокують створення задач за розкладом. | Імпорт усе одно відбувається на початку сесії й у `task-summary`, тож розклад необов'язковий. |

## Що НЕ спільне
- Вбудована пам'ять claude.ai і знання проєктів лишаються як є: набір додає копію, а не замінює їх.
- Секрети: автокопія не бере `.env`, ключі, сесії. Ніколи не пишіть у файли пам'яті паролі, номери карток чи паспортні дані — вони йдуть на GitHub і Диск.
